# nadir

A Go reimplementation of the LLM routing model first prototyped in
[NadirClaw](https://github.com/doramirdor/NadirClaw): an OpenAI-compatible
HTTP proxy that classifies prompts with a small embedding model and routes
each request to the cheapest model that can handle it.

`nadir` is a clean-room derivative — it shares NadirClaw's design (tiered
routing, centroid-based zero-LLM classifier, OpenAI-compatible proxy shape)
but has its own module path, binary name, env-var prefix (`NADIR_*`),
and config directory (`~/.nadir/`). The upstream NadirClaw Python project
is credited in `LICENSE`.

## Use cases

`nadir` ships as **both a standalone binary and a Go library**.

- Want a drop-in OpenAI-compatible proxy with cost-routing? → run `nadir serve`.
- Want to embed the routing decision in your own Go service or agent loop? → `import "github.com/qiangli/nadir"`.

## Quick start — binary

```bash
go build -o nadir ./cmd/nadir
NADIR_OPENAI_API_KEY=sk-... ./nadir serve
```

In another shell:

```bash
curl -N -H 'Content-Type: application/json' \
  -d '{"model":"auto","stream":true,"messages":[{"role":"user","content":"hi"}]}' \
  http://localhost:8856/v1/chat/completions
```

Look for the `X-Routed-Model` and `X-Routed-Tier` response headers — they
report what the classifier picked.

## Quick start — library

```go
import (
    "context"
    "fmt"

    "github.com/qiangli/nadir"
    "github.com/qiangli/nadir/classifier"
    "github.com/qiangli/nadir/router"
)

func main() {
    // Cheapest: heuristic classifier, zero deps, runs in microseconds.
    cls := nadir.NewHeuristicClassifier()
    tier, score, conf, _ := cls.Classify(context.Background(), "Design a sharded queue")
    fmt.Printf("%s (score=%.2f conf=%.2f)\n", tier, score, conf)

    // Production: load the ONNX MiniLM classifier (-tags onnx build,
    // assets generated by tools/export-onnx/export.py).
    // cls, err := classifier.NewONNXFromAssets("./assets", classifier.DefaultThresholds())

    // Full routing pipeline:
    cfg := &router.Config{
        SimpleModel:    "claude-haiku-4-5-20251001",
        ComplexModel:   "claude-opus-4-6-20250918",
        TierThresholds: [2]float64{0.35, 0.65},
    }
    r := router.New(cfg, cls, /*sessionCache*/ nil, /*health*/ nil)
    decision, _ := r.Route(context.Background(), &nadir.ChatRequest{
        Model:    "auto",
        Messages: []nadir.Message{{Role: "user", Content: []byte(`"hi"`)}},
    }, &nadir.User{ID: "demo"})
    fmt.Printf("→ model=%s tier=%s chain=%v\n",
        decision.Model, decision.Tier, decision.FallbackChain)
}
```

## Subcommands

- `nadir serve` — run the proxy
- `nadir setup` — interactive first-run wizard (writes `~/.nadir/credentials.json`)
- `nadir auth <provider> --token <key>` — store an API key (OAuth deferred to Phase 5)
- `nadir report --since 24h [--by-model] [--by-day] [--html]` — usage report from SQLite
- `nadir savings --since 7d [--baseline opus]` — cost saved vs an always-premium baseline
- `nadir budget` — current daily/monthly spend snapshot
- `nadir models` — cost / context / vision table
- `nadir dashboard --addr :8857` — single-page HTML dashboard
- `nadir skill-route --skills <file.json> --prompt <text>` — pick the best slash-command / tool name for a prompt from a JSON catalog (see "Skill routing" below)

## Skill routing

`nadir` also routes a prompt to a **skill / slash-command** (e.g.,
`/review`, `/security-review`, `/init`) — same library, different
output. Useful as a pre-dispatch step in agentic CLIs.

### Defining a skill

```go
skill := nadir.Skill{
    Name:        "/security-review",
    Description: "Audit pending changes for security issues",   // shown to LLM
    Examples: []string{                                          // embedded as prototype vectors
        "audit this branch for vulnerabilities",
        "find security issues in the diff",
        "check the auth changes for problems",
    },
}
```

`Examples` are the load-bearing field — 3–10 paraphrases per skill is
the sweet spot. Trigger phrases you'd otherwise hand-write as regex
go here. The embedder generalizes paraphrases that a regex can't.

### Two production paths

```go
// (a) No-deps default: pure-Go TF-IDF over the catalog. ~94% top-1
// accuracy on the bundled eval corpus. ~1.6 µs per Route call.
matcher, err := nadir.NewLexicalSkillMatcher(skills)

// (b) Recommended when Ollama is available: TF-IDF primary handles
// the easy ~80% of prompts in microseconds; LLM rerank fires only
// on the uncertain shortlist. ~97% top-1 accuracy with qwen2.5:7b.
llm := openai.New("ollama", "http://localhost:11434/v1", "")
matcher, err := nadir.NewHybridSkillMatcher(ctx, llm, "qwen2.5:7b", skills)

// Both return skillrouter.Matcher — same Route(ctx, prompt) interface.
decision, _ := matcher.Route(ctx, "audit this branch for vulnerabilities")
// decision.Skill == "/security-review"
// decision.Confidence == top-1 score (cosine for primary, parser-derived for LLM)
// decision.Margin     == top1 - top2 cosine gap (the cascade trigger)
// decision.FellThrough == true iff no candidate above threshold
```

### When to pick which

| Constraint | Pick |
|---|---|
| Static binary, no daemon, no CGO | `NewLexicalSkillMatcher` |
| Ollama available, want best quality | `NewHybridSkillMatcher` (recommended) |
| MiniLM-quality embeddings via Ollama, no LLM rerank | `skillrouter.NewSemantic` with `skillrouter.NewOllamaEmbedder(ctx, "http://localhost:11434", "mxbai-embed-large")` |
| CGO available, want ONNX MiniLM | `skillrouter.NewSemantic` with `embed.Open("./assets")` (requires `-tags onnx`) |
| Prototype / small catalog, want LLM-only routing | `nadir.NewSkillRouter` |

The matchers all satisfy `skillrouter.Matcher` so they're swappable
without changing call sites. Power-user building blocks
(`skillrouter.NewSemantic`, `NewCascade`, `NewFusedSemantic`,
`NewEnsemble`, `NewTFIDFFromSkills`, `NewHashEmbedder`,
`NewOllamaEmbedder`) remain public for finer control.

### Eval harness

`tools/skillrouter-eval` runs a labeled corpus through every available
embedder + composite matcher and prints a Markdown comparison
(top-1 accuracy by hardness tier, OOD rejection, latency p50/p95).

```bash
# Default build: pure-Go + Ollama probes
go run ./tools/skillrouter-eval

# Add MiniLM-via-ONNX as a comparison row
NADIR_ONNXRUNTIME_PATH=/opt/homebrew/lib/libonnxruntime.dylib \
  go run -tags onnx ./tools/skillrouter-eval --assets ./assets

# Override the LLM rerank model used in the Cascade row
NADIR_CASCADE_LLM_MODEL=qwen2.5:7b go run ./tools/skillrouter-eval
```

Findings on the bundled corpus (`testdata/skillrouter_eval_corpus.json`):
- **Cascade(TF-IDF + qwen2.5:7b)**: **97.1% top-1** — best overall.
- **Ollama:mxbai-embed-large**: 94.1% top-1 + 100% on the hardest overlap tier — best single-call embedder.
- **Pure-Go TF-IDF**: 94.1% top-1 at 1.6 µs — best when no Ollama is available.
- **Ollama:all-minilm** matches ONNX MiniLM numerically — the ONNX/CGO path is no longer the only way to get MiniLM-quality embeddings in nadir.

### CLI

```bash
cat > skills.json <<'EOF'
[
  {"name": "/review", "description": "Review a pull request",
   "examples": ["review this PR", "look at my diff", "check the code change"]},
  {"name": "/security-review", "description": "Audit for security issues",
   "examples": ["audit for vulnerabilities", "check for security holes"]},
  {"name": "/init", "description": "Initialize CLAUDE.md",
   "examples": ["set up CLAUDE.md", "create the agent guidance file"]}
]
EOF

# Lexical: no LLM, instant. Default when no model is configured.
nadir skill-route --mode lexical --skills skills.json --prompt "audit this branch"

# Hybrid: TF-IDF primary + LLM rerank on uncertain cases. Default
# when NADIR_CASCADE_LLM_MODEL is set.
NADIR_CASCADE_LLM_MODEL=qwen2.5:7b \
  nadir skill-route --mode hybrid --skills skills.json --prompt "audit this branch"

# LLM-only: one upstream call against a flat catalog.
NADIR_CASCADE_LLM_MODEL=qwen2.5:7b NADIR_CASCADE_LLM_TIMEOUT_SEC=60 \
  nadir skill-route --mode llm --skills skills.json --prompt "audit this branch"
```

Unparseable replies and out-of-catalog picks always yield
`{"fell_through": true}` — no matcher silently picks the closest
skill. The caller decides what to do on fallthrough.
For Semantic / Cascade production use, integrate the library directly.

## Classifier modes

Three tiers of routing intelligence, stackable:

1. **Heuristic** (default, always available) — length + code-fence
   detection + keyword regex. Zero deps, ~microseconds, catches obvious
   cases but misses semantic intent.
2. **MiniLM via ONNX** (with `-tags onnx` + assets) — real embedding
   classifier matching NadirClaw's behavior within 1e-4 numerically,
   ~8 ms/classification. See below.
3. **Cascading with LLM second opinion** (with `NADIR_CASCADE_*` env)
   — wraps either of the above; when confidence is below a threshold,
   asks a small local LLM (default: Ollama llama3.2:3b) to break the
   tie. Adds ~300–500 ms on uncertain requests only.

### MiniLM via ONNX

Generate the ONNX assets and rebuild with the `onnx` build tag:

```bash
# 1. one-time export
python -m venv .venv && source .venv/bin/activate
pip install -r tools/export-onnx/requirements.txt
python tools/export-onnx/export.py

# 2. install onnxruntime shared library
brew install onnxruntime       # macOS
# sudo apt install libonnxruntime-dev   # Debian/Ubuntu

# 3. rebuild
go build -tags onnx -o nadir ./cmd/nadir

# 4. (optional) override the shared library path
NADIR_ONNXRUNTIME_PATH=/opt/homebrew/lib/libonnxruntime.dylib ./nadir serve
```

`nadir serve` logs which classifier it picked at startup:

```
INFO classifier: onnx assets=assets
INFO classifier: heuristic (no ONNX assets at assets)
```

Numerics match the Python reference within `1e-4` per the goldens in
`testdata/classifier_golden.json` (generated by the export script).

### Cascading with LLM second opinion

Wraps the primary classifier (heuristic or ONNX). When the primary's
confidence falls below `NADIR_CASCADE_THRESHOLD`, the cascade asks a
small local LLM to break the tie. On confident requests the LLM never
runs, so the average overhead stays low.

```bash
# Run a small model on Ollama
ollama pull llama3.2:3b
ollama serve

# Enable cascade
export NADIR_CASCADE_THRESHOLD=0.4      # consult LLM when confidence < 0.4
export NADIR_CASCADE_LLM_MODEL=llama3.2:3b
export NADIR_CASCADE_LLM_BASE_URL=http://localhost:11434/v1
export NADIR_CASCADE_LLM_TIMEOUT_SEC=2  # fall back to primary on LLM timeout

./nadir serve
```

Boot log:
```
INFO classifier primary: onnx assets=assets
INFO classifier: cascading threshold=0.4 llm_model=llama3.2:3b llm_base_url=http://localhost:11434/v1
```

When the LLM is unreachable or times out, the cascade silently falls
back to the primary verdict — routing always produces an answer; the
worst case is a single suboptimal route, not a 500.

## Migration from NadirClaw

`nadir` ships its own env-var prefix and config dir. To migrate:

| NadirClaw | nadir |
|---|---|
| `NADIRCLAW_OPENAI_API_KEY` | `NADIR_OPENAI_API_KEY` |
| `NADIRCLAW_SIMPLE_MODEL` | `NADIR_SIMPLE_MODEL` |
| `NADIRCLAW_COMPLEX_MODEL` | `NADIR_COMPLEX_MODEL` |
| `NADIRCLAW_TIER_THRESHOLDS` | `NADIR_TIER_THRESHOLDS` |
| `~/.nadirclaw/` | `~/.nadir/` |

Semantics are preserved — a `sed -i 's/NADIRCLAW_/NADIR_/g' ~/.bashrc`
plus `mv ~/.nadirclaw ~/.nadir` is sufficient.
